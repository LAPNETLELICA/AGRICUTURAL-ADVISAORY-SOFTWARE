AgriAdvise Mobile Frontend API Handoff

Backend contract and user-flow guide for the mobile application

Base URL: https://<host>/api/v1. Send Authorization: Bearer <token> for authenticated endpoints. Use JSON unless an endpoint explicitly accepts a multipart media upload.

Download this document: GET /api/v1/documentation/mobile-frontend-handoff. The response is a PDF attachment.

Source of truth: The backend selects agricultural advice. The app only collects context and presents the recommendation, action steps, warnings and contacts it receives. Do not place API keys, Tranzak credentials, or farmer telephone numbers in the mobile app.

1. Farmer mobile journey

  1. Account: register or sign in, then securely save the returned access token.
  2. Profile: load the farmer profile and save language/knowledge level. Use this to choose simple or detailed presentation.
  3. Guided help: start a questionnaire with region and locality. Display one question at a time.
  4. Every question: show the supplied options and a text box. Include “I do not know”. The farmer may choose an option or type a different issue.
  5. Adapt: submit the selected value or free text. The next question can change according to their issue, profile, crop passport and known locality facts.
  6. Recommendation: when enough context has been supplied, call completion. Stop asking questions and render the returned recommendation.
  7. Follow-up: allow a new guided-help session or direct mobile-advisory request without overwriting the earlier recommendation.

Location behavior: region/locality facts are checked before asking location-related questions. The app must not force a terrain question when the backend already knows the relevant local context. When information is absent, display the next backend question.

3. Voice and picture input

  • Voice-to-text: upload file and optional language to POST /advisory/transcribe. Put returned text in the same free-text questionnaire input for the farmer to confirm/edit.
  • Voice answer: POST /advisory/voice creates spoken advice where the configured provider is available.
  • Picture evidence: upload file, farmer_id, optional crop_id and request_id to POST /media/images. Keep the returned image_id and include it in evidence.image_references.
  • Optional image assessment: call POST /image-analysis with image_id, optional crop_id, and analysis_type. It is supporting evidence, never a substitute for farmer description or backend recommendation.

Regional SMS administration

These administrator-only endpoints manage phone number plus Cameroon region only; they do not store crop, passport, or recommendation context.

  1. GET, POST /admin/sms/registrations: list or register recipients.
  2. POST /admin/sms/broadcasts/preview: show the exact active recipient count before confirmation.
  3. POST /admin/sms/broadcasts/send: after confirmation, re-resolve active recipients, send, and return sent, failed, and recipient_count.
  4. GET /admin/sms/deliveries?limit=100: display SMS history.

Use {"kind":"region","region":"South"} for a regional message or {"kind":"cameroon"} for a Cameroon-wide message. Automatic SMS is separate from normal recommendations: only validated, explicitly scoped alerts are eligible, and the worker remains idle without them.

6. Error and security behavior

  • 400/422: show an input-specific validation message and keep the entered form data.
  • 401: refresh/re-authenticate, then retry only after the user signs in.
  • 403: show that the content is not owned by the current farmer or requires a higher role.
  • 404: show unavailable content; do not guess identifiers or agricultural content.
  • Never log bearer tokens, voice files, image files, farmer phone numbers or API credentials in the mobile client.
